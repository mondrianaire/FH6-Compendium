## 1. Artboards

There is **exactly one artboard** in this file — no "as shipped" or recreation artboard is present here.

- `data-screen-label="Course mode v2 — every verdict carries its basis"`, `width:1080px;height:1751px`, `background:#0d1117;color:#dfe7ef`. This IS the target design for the redesign (not a duplicate/comparison). **Ordering caveat to flag:** the DOM order of top-level bands is 1 (top strip), 2 (header), then SCOPE band markup appears next in source but is tagged `order:5`; then the course-identity/laps-by-class band appears (no explicit order, defaults to its source position — flex `order` default is 0, so it actually renders FIRST among the flex children unless computed otherwise). Given the explicit `order` values found (`order:5` scope, `order:3` course-identity band, `order:2` held/build band, `order:4` speed-trace band, `order:6` main body, `order:7` footer), the effective visual stacking by order number is: header(no order/0-ish)→ course-identity(order 3) sits after held/build(order 2) sits after nothing... Re-checking: explicit orders found in file are `order:5` (scope), `order:3` (course-identity/laps band), `order:2` (held/build band), `order:4` (speed-trace band), `order:6` (main grid), `order:7` (footer). Top strip and header have no order attribute (default 0). ### 4h. Course map + legend bar + follow camera HUD (left pane, 452px wide; map area flex:0 1 346px min-height 274px)
Overlay control bar (30px, absolute top, semi-transparent `rgba(13,17,23,.82)`): **follow** button, **whole course** button (mutually exclusive, toggling `this.state.cam`), then when `cam` is true: play/pause icon button (⏸/▶) + state readout (`{{camCtl.state}}` — "in T8" or "T8 in 42 m" — plus `{{camCtl.read}}`, e.g. "63 mph · understeer · trail painted by grip · 71 mph typical apex").
Map SVG (`viewBox 0 0 452 346`): layered polylines — history laps (green, low opacity), fastest-lap overlay (blue), centre-line (grey, thicker), casing (black, width driven by `map.casingW`: 21 when camera-following, 11 in whole-course view), colored 5-phase ribbon bands for the selected/ahead turn, tick-mark dividers between phase bands, trail-runs (see below), and markers layer (`map.markers`, raw `E()`-built SVG group): every turn's apex gets a dot + "T#" label at all times; when following, the **active/ahead turn** gets a larger white-ringed dot, a bold "T#" (21px, drop-shadow via paintOrder stroke) offset further out, plus its kind text (`t.kind.toUpperCase()`) in amber; the car itself is drawn as a rotated triangle (`polygon points="13,0 -8,7 -8,-7"`) with a soft white glow circle, rotated to face travel direction (`ang`, computed from the previous camera-interpolated point).
**Follow camera** (`camProj()`): damped rig — pans 12% of the way to target center per tick (`k=0.12`), zooms 7% per tick (`kz=0.07`); target center is a weighted blend `tcx = midpoint*0.45 + carX*0.55` (55% bias toward the car, per handoff spec); needed span = `max(dx, dz*aspect, 110) * 1.3` (110 m minimum, 30% margin); interpolation is fractional-index (`ti` state advances by 0.25 per 45ms tick — a quarter-point per tick because stored samples are ~17m apart and a full point would read as a hop); camera state persisted across renders in `this.camView` (not React state) so damping carries over. Turn "ahead" stays the camera subject until its straight run ends (`aheadT` found via `turns.findIndex(t => t.spans.straight[1] > carS)`), preventing mid-corner subject flips; a `leaving` turn (within 70 m of the previous turn's straight end) is drawn faded (opacity 0.2) so phases don't pop discontinuously between corners.
**Trail**: built as one polyline run per contiguous color (`grip` or `speed` paint), not one single multi-color stroke — `map.trail`, run opacity ramps `0.3 + 0.7*(i/runs.length)` so older segments fade; the newest run is extended to the live interpolated car position so the trail never lags visually.
Legend/basis **bar** below the map, height **74px** total: top 24px row = 4 overlay toggle buttons (`overlays`: centre-line #8fa0b3, laps drawn #00d27a, fastest lap #4ea3ff, 5 phases #f0b429), each showing a swatch, title, and right-aligned state text (count/on/off); bottom ~50px = 3 basis lines (`overlayBasis`, one per toggled layer, format `<bold colored key> <value text>` e.g. "laps drawn 45 of the 45 in history · all classes · the 20 older laps have no stored line", or "hidden — …" when the layer is off).

## 5. JavaScript logic summary

- **`arm()`/timer** — camera playback loop: `setInterval` every **45ms**, advances `ti` by **0.25** per tick (quarter-point steps because trace samples are spaced ~17m apart); wraps to 0 and clears `camView` when it reaches lap end. Runs only when `state.cam && state.playing`.
- **`proj(sets, W, H, pad)`** — generic point-set → SVG-space projector; fits bounding box of all input point sets into `W×H` minus `pad`, uniform scale (`Math.min` of x/y scale) to preserve aspect, centers the result.
- **`bandPts(a,b)` / `ptAt(s)` / `tangentAt(s)`** — arc-length utilities over the course centerline (`this.arcCache`, cumulative distance array built once); `ptAt` linearly interpolates position at arc-length `s`; `tangentAt` samples ±5m around `s` for a direction vector.
- **`phaseRibbon(turn, projector, width)`** — turns a turn's 5 phase spans into one continuous casing polyline + per-phase colored band polylines + perpendicular tick-divider lines at each phase boundary (normal computed in screen space so dividers stay perpendicular under non-uniform projection). Fixes an earlier bug where overlapping ±4m phase slices, drawn as separate round-capped strokes, bulged into each other; now cut exactly at boundaries and drawn butt-capped over one casing.
- **`camProj()`** — the follow-camera implementation. Constants: pan easing `k=0.12` (12%/tick), zoom easing `kz=0.07` (7%/tick), center bias `0.45` bbox-center / `0.55` car position, minimum span `110` (map units) with `1.3×` margin. Persists `this.camView` across renders (not component state) to keep damping continuous. Determines `aheadT` (turn the camera should frame) via first turn whose straight-phase end is still ahead of the car's arc position, and a `leaving` turn (previous turn if within 70m of its straight end) drawn faded for continuity.
- **`paintOf(point)`** — chooses trace/trail segment color: `speed` mode buckets into 5 bins of `SPEED_RAMP` by normalized speed; `grip` mode indexes `TRACE_GRIP` by the point's stored grip-state integer.
- **Trail/run builder** (inline in the camera branch and again for the speed-trace band, same pattern) — walks a lap's samples and slices it into contiguous same-color runs, so a multi-color polyline set is emitted per run rather than one polyline (SVG can't per-vertex-color a single `<polyline>`).
- **Rank/degenerate-pool rule** (`lapRowsRaw` map, and `board()` helper reused for the two turn-window leaderboards) — pool = only passes matching the active `cls` scope filter (never all-class silently relabeled — explicit design comment: "ranking the all-class passes and then labelling them A·7 would be a false provenance"); "current" pass for a turn is deliberately the **median-index pass**, not the fastest (comment: picking the quickest would rank first by construction, "the exact defect the handoff's §1 describes"); `thin = n < 5`; `level` (degenerate, no winner possible) when `n < 2 || poolBest === poolWorst`; confidence marker `★` (full) vs `☆` (weak, thin pool) only awarded when `isBest && !level`.
- **`RULES` diagnosis table** — keyed `"<phase>|<axle>"` (axle: 1=front/understeer, 2=rear/oversteer, 3=all-four/drift, 4=impact) mapping to `[ruleId, headline, fixText, toneColor]`; falls back to `"any|N"` when no phase-specific rule exists; `"any|3"` (all-four slide) deliberately has `ruleId: null` ("No rule card fires on a four-wheel slide"). Fault-detection picks, per phase, whichever non-grip axle has the largest `mix[i]` share, scores it by `share × phase_time`, and keeps the single highest-scoring phase across the turn as `fault`; confidence gate is `fault.laps >= 5` traced laps ("measured" vs "need more · N of 5").
- **Sorting** — turn list: `route` (by seq) vs `find` (by descending `avail_s`, time available to gain). Lap-rank table: `turn` (seq order), `rank` (ranked rows first, ascending rank), `delta` (descending gap-to-best). Pool table: `time` vs `cls`. Car table: `laps` (descending, name tiebreak) vs `best` (ascending, unset-times sorted last).
- **Scope switching** (`scope.match`) — one-click toggle: if scope currently mismatches the car's class, jump straight to that class; otherwise revert to `all`.
- **Build-guard walkthrough** (`build.walk`, tie state only) — cycles `this.state.equip` 0→4 (mod 5) on each CTA click, driving both the 4-step highlight strip and the CTA's own step-labeled text; step 4 flips the CTA to "✓ tune decoded — re-read the save ▸".
- **Statistics reconciliation** (`clsStat.basis`) — compares `claimed` (the SCOPE band's own class lap-count, from `CLS_LAPS`) against `attributed` (laps actually summed from `H.meta.visits`, split evenly across cars sharing a session); if they disagree, the basis line turns amber and states how many "older laps name none."

## 6. Contradictions, additions, and ambiguities vs. the handoff summary

- **No separate "as shipped" or comparison artboard exists in this file.** Only one 1080×1751 artboard is present. If a shipped/reference artboard is expected for the handoff, it lives in a different file (e.g. the "Current (as shipped)" build referenced in repo commit `75900a7`, "refresh src to shipped code + brief the upgrades") — not here.
- **Legend bar height matches the handoff exactly (74px)** and does sit directly under the map with layer toggles (top 24px) + basis lines (bottom ~50px) — confirmed, no contradiction.
- **Follow-camera constants match the handoff** (12% pan / 7% zoom easing, 55% car bias, fractional-index interpolation, per-colour trail runs, "T8 in 42 m"/"in T8" HUD, apex-labels-only-when-on-screen) — all directly confirmed in code with exact constants documented in §5.
