## The pattern, and the one rule

The rewrite kept v1's SHAPES and dropped its JUDGEMENTS: the panes, the trace, the corner log and the status machine all came across, but the fields that say how sure, from where, and against what did not — so columns that are already exported sit unread (course.profile 60/60 rows, corner_obs 2,546 rows, ref_symptom.verify_test, lap_point.elev_m 79k rows, ref_car.in_autoshow 171 un-buyable cars, diag.json symptoms, union.fields), and the daemon's own verdicts (match.stale, how='unsaved-build', held, ladder_tied, diff_base, gear_diag) are re-derived client-side in weaker form or ignored. Where v1's lessons were mostly about REFUSING to assert — confidence tags, void/partial kept and struck, 'no grip reading' not 'not driven', offline is not an identification failure — v2 asserts flatly: a green RATIFIED pill over open save-vs-telemetry conflicts, a bare 'front ARB softer' chip with no current value, 'no save on disk for this car' when the daemon is merely down, and a green 'fastest' line on a lap 8.3 s off the actual fastest. Compounding both, the caps added for file size (8 traces per course, one per cid, void and partial dropped) silently became the denominator the UI reports as truth — 51 traces for 319 laps, a 99-lap course whose header reads '2 of 2 laps on record'. THE ONE RULE THAT WOULD HAVE PREVENTED IT: never render a number or a claim without also rendering where it came from and how sure it is — which forces the corollary that a field exported must be rendered or not exported, and a verdict that already exists upstream must be read, never re-derived.
