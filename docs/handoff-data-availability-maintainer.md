## 3. The model you must preserve (two axes)

Every data node carries **both** tags. Do not collapse or rename these axes without cause.

- **Value type** (which game system it describes/impacts): `ID` car-identification · `TEL` driving-telemetry ·
  `CRS` course/track/position · `TUN` tuning/parts/sliders · `LAP` lap-history/race-timing · `INP` driver-input ·
  `STR` reference-strings.
- **Provenance** (where it comes from + sanitized-branch disposition = the diagram's group colour):
  - **official-feature** (green) — the *Data Out* UDP telemetry, the only dev-supplied live source → **keep**.
  - **live-decode** (red) — game private files decoded at runtime while the daemon serves → **the sanitization target**.
  - **decoded-once-committed** (blue) — game files decoded offline by `rebuild.py`, committed into `fh6.db` → **freeze**.
  - **derived-ours** (teal) — our own computation, no game data → **keep**.

The boundary line, verbatim: *a field present in the 324-byte Data Out packet is official and sanctioned;
anything pulled from a decoded save, database, or BXML/zip artifact is derived and unofficial — no matter how
thoroughly cross-verified.*

Do not churn the artifacts for cosmetic reasons; a stable reference is more valuable than a busy one.

## 6. How to regenerate the classification (the audit method)

When code has changed materially, **re-run the provenance audit** rather than hand-patching guesses. It was
originally a 4-agent parallel workflow (agents default to **Sonnet** per Jett's rule); reproduce it:

1. **daemon-runtime-decode** — read `scripts/telemetry/fh6_live_daemon.py`, `fh6_tune_decode.py`, `fh6_anchors.py`.
   List every dependency that decodes a **game file** (save / livery / install / game-db) **at runtime while
   serving**, vs reads that are the UDP feed or our own committed stores. Cite file:line. (Baseline result: four
   live-decode sites — `Tuning_*/Data` decode, livery header+thumb, `ContainersRoot` re-glob, `race_triggers.tz`
   re-parse — plus a `build_web.py` build-time leak; the daemon's sqlite reads are our own `fh6.db`, read-only.)
2. **import-pipeline** — `scripts/db/rebuild.py` + `import_*.py` + `build_web.py` + top of `analyze_session.py`.
   Classify each as offline-import vs runtime; map game_source → output_store. (Baseline: all offline; `build_web.py`
   is DB-only except the two leak spots.)
3. **inventory-value-map** — from `docs/DATA-INVENTORY.md` + `db/schema.sql`, tag every source/store with
   value_types + provenance + location.
4. **dataout-feature** — `scripts/telemetry/fh6_dataout_capture.py`: the exact 324-byte field list grouped by
   value-type; confirm it is the sole dev-supplied live source.

Each agent returns structured JSON (name, location, provenance, value_types, runtime_live, where, note). Synthesize
the four into the matrix, then update the three artifacts. Keep agents on Sonnet unless a step genuinely needs more.
