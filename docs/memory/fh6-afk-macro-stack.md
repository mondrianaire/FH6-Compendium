Jett's FH6 AFK farm runs on DS4Windows 3.3.3 (portable install at `C:\Users\mondr\Downloads\ds4windows-3-3-3 (1)\DS4Windows\`). Macros are Special Actions in `Actions.xml` — **edit the XML directly with DS4Windows closed** (Stop-Process, backup, DOM-edit Details, relaunch); the GUI Load Preset path corrupted a macro once, so avoid GUI round-trips for generated macros. GOTCHA: a Special Action only FIRES if its Name is also listed in the active profile's `<ProfileActions>` (in `Profiles/<name>.xml`, `/`-joined) — defining it in `Actions.xml` alone isn't enough. Also: DS4Windows loads config at launch, so after editing XML you MUST restart the process for it to take effect (a stale instance keeps the old bindings).

ROOT CAUSE 2026-07-29 (Jett's catch): the farm's car-select picks from the FAVORITES list, and the Revuelto cycle favorites each Lambo it buys — so any failed removal left a favorited Lambo that got selected instead of the 22B, silently killing the 9x chain multiplier and starving the whole economy. Fix: inject View (jump-to-manufacturer) + 1 right + A into the car-select so it anchors on Subaru whether or not stray Lambos exist (one right = Subaru when Lambos present, clamps to Subaru when not). CRITICAL placement lesson: it must go AFTER the B that closes the filter dialog — the A between Y and B is the filter's own confirm, and injecting before B corrupts it. General principle (now standard): every block must ESTABLISH its own preconditions, never trust an upstream block's cleanup.
