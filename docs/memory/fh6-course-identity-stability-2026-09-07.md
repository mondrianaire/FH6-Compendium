Jett reported three course-identity defects on 2026-09-07 (branch claude/forza-eliminator-tips-db-c512c3). Root causes and status:

**1. Reverse drive mis-IDs as a neighbouring course (Sekibe Scramble).** "Goliath Colossus Street Track" is the NAME OF A DOWNLOADED TUNE (`tunes[0].name` on the Centenario build a04bb37d06356b53), NOT a course — a red herring. The actual course the user drives shares a spawn PLAZA with Sekibe Scramble. In that plaza there are exactly two catalogued routes: `route:30003` "Sekibe Scramble" (DIRT, start [2493,-5046], heading [-0.118,-0.993], 2134 m, 27 events) and `2500_-5050` — an UNNAMED geometry-keyed course, same start/heading, ~2124 m, **122 events, and NO course file was written** (routes.json has it, `data/courses/2500_-5050.json` does not — a plumbing gap like [[fh6-course-file-colon-bug]]). Because the street circuit is unnamed, the daemon falls to the nearest NAMED start = Sekibe (19 m away). The daemon's live matcher (`_match_learned_start` 60 m, `_match_route_name` 120 m, `_catalogue_match` ov/cov) is 100% direction-blind. The analyzer IS directional (`direction_agree` analyzer:1734; `_catalogue_key` gate 1901 with comment "a course driven the other way is a different course"; `attribute_route` heading-dot <0.3 at 1807) and by design treats reverse as a DIFFERENT course — that gate was added to stop reverse roll-ups minting garbage keys (e.g. "-3550_400" from Colossus backwards). **Jett chose: recognize reverse as the SAME course** (keep identity + turn analysis). ANALYZER HALF SHIPPED (commit 8fffea9): `_catalogue_key` now accepts a reverse lap of a CLOSED LOOP (is_loop from path closure, cov≥0.6) as the same course key, tags it `reverse`, and keeps reverse laps OUT of the forward corner model (`fevs` filter — cc/ll/bb/cr/pulses/bott scope to forward laps) so per-turn stats aren't corrupted. No-op for forward-only sessions by construction; deploys live via the analyzer subprocess (no restart). DAEMON live-label: investigated live 2026-09-07 with a background SSE capture (scratchpad/plaza_cap.py) during a forward+reverse drive of The Goliath (the 25-min course that had read as Sekibe). It did NOT reproduce — the daemon held "The Goliath" (route:5555, start [4190,-5481]) continuously through both directions. Consistent with the matcher: Goliath's start is ~1.7 km from Sekibe's plaza (outside the 60/120 m radius), so a Goliath spawn can't match Sekibe, and once `_ev_named` locks an unambiguous learned start the path-match is skipped so the name holds regardless of direction. Conclusion: no blind daemon fix — the matcher behaved correctly; the earlier "Sekibe" was a transient/stale state compounded by the broken-map + shares-road-backup bugs (both since fixed). If it recurs, capture WHICH course + the live loop before editing the live matcher. (b) `2500_-5050` needs a real name + its missing course file. (c) reverse-DIRECTION turn view (bucket turns by direction) — a follow-on; today reverse laps show identity+map but no reverse turn stats.

**2. Broken map (thin vertical squiggle). SHIPPED (commit 48fcbaa).** `courseMap()`/`bounds()` in app.js drew the stored course geometry; `bounds()` had no non-finite guard and only rescued an EXACTLY-zero span, so one outlier/NaN coord collapsed the loop. Fixed: `bounds()` ignores non-finite coords; new `robustBounds()` scales to the 2nd–98th percentile per axis (outliers still draw, don't set scale). app.js?v=95.

**3. Goliath map "CONSTANTLY switching". SHIPPED (commit 2aa98d2).** Client-side: a long/offset-start event (the Goliath's S/F doesn't resolve to a start → daemon says "Rivals course" → client `LOOP` null) runs `locateCourse()` every frame, which flips COURSE among the many short learned courses the 85 km route threads through (incumbent 25 m hysteresis can't hold on shared tarmac). Fix: in an event with no daemon loop, skip learned-course proximity matching and let `locateRouteInEvent` name the stable catalogued route (its longest-route-wins tie-break holds the Goliath). Gated to `event && !LOOP`. panel.js?v=124.

The daemon renames its loop AT MOST ONCE then locks (`_ev_named`, fh6_live_daemon:548-560), so the daemon is not the flap source; the flap is client `locateCourse`. Extends [[fh6-course-corroboration-hierarchy]], [[fh6-course-keying-catalogue]]. Standing rule reminder: never restart the live daemon without asking; analyzer changes deploy live via subprocess, daemon in-process changes need a restart.
