Verified 2026-09-11 (workflow read build_web.py / analyze_session.py / import_corners.py / schema.sql / fh6_live_daemon.py). This is the data available to the "Turn analysis" view (`turnStatsHTML`/`cornerMapHTML`, panel.js), and the persist-vs-discard truth that decides what's buildable.

**The web TRACE point** = `[arc_m, mph, grip_code, x, z, elev_m, thr%, brk%]`.
- `grip_code` (index 2): 0 within-grip / 1 understeer / 2 oversteer / 3 drift / 4 impact. **BASE schema → present on EVERY lap ever recorded (full history).** I once misremembered index 2 as a flag; it is the grip state. It maps through `GSTATE`/`DGRIP` (panel.js ~481). The **grip overlay** (corner-map "grip" toggle, `gripInk(b[5])`) ships off this — no pipeline change (built 2026-09-11, `cf043c6`).
- `thr%`/`brk%` (index 6/7): schema-6, **NULL on laps before 2026-09-10** — any pedal insight must graceful-degrade. Stored columns are normalised 0–100% (`analyze_session.py ~2772`); use `pedalKey()`'s 10/40/90 bands, NOT the live daemon's raw-byte literals (its brake-on is `brk>40` on a 0–255 byte ≈16%, vs throttle ≈39% — an inconsistency in the daemon, see [[fh6-pedals-recorded-forward]]).
- Per lap×turn×phase, `phaseObs` carries `mix[5]` (grip-state sample counts), `time_s`, `apex_mph` — grip as a per-phase distribution.

**Discarded, NOT persisted (decides v2/v3 of the roadmap):**
- **Raw lateral-g / long-g / per-wheel slip** are decoded every UDP packet but thrown away the instant `grip_code()` collapses them to 0–4. Precise grip ceiling `a_max` in g → needs a **schema-7** `lap_point` column, **future drives only, no re-drive** of old laps. BUT the grip-limit SPEED per turn can be **bracketed now** from `grip_code`+`mph` (highest apex mph grip held vs lowest where it broke) → a v1 per-turn optimality/grip-utilisation rating is buildable on full history.
- The live daemon **already computes** per-corner `brake_on_m`, `throttle_on_m`, understeer index, `first_red`, `kink`, `brake_max`, `hb` every drive — then discards them (`ST.corners` capped 60, live-SSE only, wiped on rescan; `build_web.py` never reads it). Persisting `ST.corners` to the session/DB is a small NEW write path, **zero new capture**.
- Extending the historical per-corner store needs `thr,brk` added to `import_corners.py`'s SELECT + `corner_segment` columns + the **rebuild cascade** ([[fh6-rebuild-cascade]]), no re-drive — this unlocks the two highest-value insights: grip-break attribution by pedal (oversteer → "82% under throttle") and lift-vs-grip time-loss split.

**How to apply:** the enriched turn-view roadmap (grip overlay ✓, descriptive stats, finding-engine with evidence, grip-envelope optimality ratings) is designed against this. v1 = dashboard-only on existing data; v2 = the small `import_corners`/`ST.corners` persistence via rebuild; v3 = schema-7 lateral-g, future drives only. Honest-ratings rule: a v1 approximation (bracketed ceiling, grip-utilisation vs precise g) must be LABELLED so it never reads as the real physics. Related: [[fh6-turn-design-language]], [[fh6-pedals-recorded-forward]], [[fh6-course-mode-v2-rework]].
